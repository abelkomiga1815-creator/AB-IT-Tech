# GROUP 3 — Student modules (projects, progress, documents, defense preparation)

Backend for the Student Project Platform (GROUP 2). Everything here belongs to a student's own profile; nothing is visible to other students, customers or the public.

```text
users 1 -- 0..1 student_profiles 1 -- 0..n projects 1 -- 0..n project_progress
                                                    1 -- 0..n project_documents (bytes on disk)
                                                    1 -- 0..n defense_questions
```

## Ownership (the core security rule)

All endpoints live under `/api/v1/student/**` (role STUDENT, enforced in `SecurityConfig`). They take the user from the JWT, resolve the student profile, and then load the project with `findByIdAndStudentProfileId`. `ProjectService.requireOwned` is the single place that does this, and progress, documents and defense questions all go through it. A project (or any item in it) that is missing or belongs to another student answers the same 404, so existence is not revealed. Child ids are always looked up inside the owned project, so a foreign document or question id cannot be reached through the attacker's own project.

## Projects and progress

A student can have several projects. Fields: title (required), description, research area, supervisor name, deadline, status (`PLANNING`, `IN_PROGRESS`, `COMPLETED`, `ARCHIVED`). Projects are archived, never deleted.

Progress is a history of entries (stage, percent 0-100, optional note). The latest entry is mirrored on the project (`currentStage`, `progressPercent`) so project lists and dashboards need no join. Stages follow the usual research flow: topic selection, proposal, literature review, methodology, implementation, writing, review, defense preparation, submission.

## Documents

- Upload as multipart; type and optional description are metadata. Accepted: pdf, doc, docx, ppt, pptx, xls, xlsx, csv, txt, md, png, jpg, jpeg; max 10 MB (`app.storage.max-file-size-bytes`, matching `spring.servlet.multipart.max-file-size`).
- Safety: whitelist by extension (no executables, html, svg, js, zip); content type derived from the extension; the client filename is sanitised (directories and control characters removed, length limited) and only used for display; files are stored under a random UUID key inside `DOCUMENTS_DIR` and a key can never resolve outside that directory; downloads are attachments with `nosniff` and `no-store`.
- If saving the database record fails after the file was written, the file is removed again.
- Deleting a document removes the record and the file. This is a deliberate, owner-only action.
- Limitations: no antivirus scanning, no content (magic-number) inspection, local disk only (`LocalDocumentStorage` is the one class to replace for object storage). The documents directory holds user data and must be on persistent, backed-up storage.

## Defense preparation

Students record the questions they expect and their prepared answers: question (required), answer, category (`GENERAL`, `METHODOLOGY`, `LITERATURE`, `RESULTS`, `IMPLEMENTATION`, `OTHER`), and a `prepared` flag. Suggestions generated by the AI engine will be added in the AI stage; this module only stores what the student writes.

## Database

V8 `projects` and `project_progress`, V9 `project_documents`, V10 `defense_questions`: foreign keys `ON DELETE RESTRICT`, check constraints for every enum and for percent/size, unique storage key, indexes on (parent, created_at).

## Validation

Project: title 1-300 characters, description up to 4000, research area and supervisor up to 150, deadline an ISO date. Progress: stage required, percent 0-100 required, note up to 2000. Defense question: 1-1000 characters, answer up to 4000. Document: file required and non-empty, description up to 500.

## Future

The AI stage will attach research analyses to projects (`research_sources`, `research_analyses`) and may suggest defense questions; both use `requireOwned` as well.
